# 电话标签录音页替换修复

## 用户实机复现

用户 2026-11-25 21:50 明确澄清：个人收藏、语音留言两个替换入口均有问题。首次点底部“录音”页面空白；下拉后才显示录音内容；再次点底部“录音”标签恢复原生个人收藏/语音留言页。不要把最后一步误记为滑动返回。

## 根因与修复边界

旧实现同时在候选导航容器及内容控制器 appearance 时叠加 child，并复制 navigationItem。它没有替换真实标签入口，也没有隔离 Phone 的重复选中/重置导航逻辑；手动 child 生命周期还可能漏掉初次列表加载。视频与用户反馈证明症状，源码可确认存在这些覆盖和生命周期风险，但没有设备调用栈证明每个私有内部回调路径。

- 仅在 MobilePhone 的 PhoneTabBarController 中，通过公开 UIKit 标签数组 setter，把识别出的目标入口替换为独立录音 UINavigationController/root；不再在原宿主上盖 child，也不改写原始导航标题、按钮或搜索对象。
- 个人收藏/语音留言各自保存 original→replacement 关联。原入口完整保留，关闭总开关或对应替换开关时恢复原入口（含原本 nil 的导航状态，无需逐项猜测恢复）。默认关闭不创建映射、不加载列表、不主动重置原数组。
- 已有 Capture 注册证据支持的四个具体内容类优先；语义类名 fallback 仅限定 Apple bundle 下真实 Phone 标签根层级并排除 CarPlay，递归深度有界，识别不明或有歧义不替换。不使用本地化标题或猜测 Phone 私有整数映射。
- 首屏在 viewDidLoad 主动 reload，保留 viewWillAppear 更新；构建替换入口时 loadViewIfNeeded。异步结果沿用已有 loadToken 校验，不依赖用户下拉。表格位于 safe area 内，禁止再次自动叠加导航栏 inset。
- 自有导航 root 受控，不允许 Phone 的 reset/push/pop 将其改为原生内容；浏览器播放为内联、分享/文件夹为 modal，不依赖 push。
- 目标标签的 delegate proxy 吸收重复点选和针对该页的 native didSelect；其他标签事件与可用的原始代理方法继续转发。代理随映射创建/撤销，并可恢复原始 nil delegate。
- 系统回写原数组或选择缓存 original 时，重新映射到 replacement。重入期间也保持过滤；未装入的选择意图延后处理。setter 结束检查实际数组，必要时一次通过 UIKit 基类公开实现修复，不无限轮询。
- 禁用标签优先于录音替换，不主动补回 incoming 中已消失的标签；取消禁用后的标签重建仍按 phone-tabs.md 完全重开电话的约定。
- 不改自动录音采集引擎、存储路径、电源执行、MUtoolRecord/MUtoolMixer；列表播放/删除/搜索/分享逻辑保持，仅修改首屏刷新与 inset。

## 验证与待真机验收

Logos + iOS16.5 SDK + modern arm64e + ARC + Wall/Werror 预检、git diff --check，以及未改采集/路径/helpers 的差异检查分别执行。编译与静态审阅不证明目标设备所有私有 Phone 重选路径已覆盖。

分别只开个人收藏替换、只开语音留言替换、同时开启：冷启动后第一次进入即见列表；不下拉也能看到已有录音；连续重复点底部录音仍留在录音页；来回切换其他标签后正常；标题/搜索/文件夹及播放器不被旧页面遮盖；空目录有明确空态；播放、搜索、分享、删除可用；关闭开关恢复原页面；隐藏+替换同时开启时隐藏优先。升级后需完全结束并重新打开电话再验收。
